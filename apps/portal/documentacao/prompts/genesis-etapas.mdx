## Objetivo

Cada etapa do Genesis tem um prompt próprio (config em `builder_prompt_configs` ou fallback em `builder.ts`) e um **contrato de saída** (`input_schema` de uma tool) que força structured output — o modelo não pode devolver texto livre.

## Localização e contexto

| Item | Valor |
|------|-------|
| Configs | Tabela `builder_prompt_configs` (schema `educacional`) |
| Fallbacks | `src/lib/builder.ts` |
| Contratos de saída | `src/lib/builder-schema.ts` |
| Modelo alvo | OpenAI via edge central (default `gpt-4.1`) ou Anthropic (`claude-sonnet-5`) |
| Usado por | `/genesis/api/etapa` → cascata do builder |

## Persona base (fallback)

```text
Você é um arquiteto de soluções que desenha soluções construíveis
com Lovable + Supabase.
```

Complementada por catálogo de preços (`price_catalog`) e regras anti-genérico (`anti_generic_rules`).

## Variáveis do template de usuário

| Variável | Tipo | Descrição |
|----------|------|-----------|
| `{{idea}}` | `string` | A ideia original do aluno |
| `{{answersContext}}` | `string` | Perguntas e respostas consolidadas da entrevista |

Template fallback:

```text
IDEIA: "{{idea}}"
{{answersContext}}

Gere o conteúdo da etapa {step_key} em JSON.
```

## As 8 etapas e seus objetivos

| Etapa | O que o prompt pede |
|-------|---------------------|
| `knowledge_base` | Base de conhecimento da solução: 5 perguntas essenciais + 3 bônus |
| `framework` | 5 pilares de implementação |
| `architecture` | Mapa mental de arquitetura e fluxos para o MVP |
| `tools` | 6 ferramentas essenciais com alternativas (usa `price_catalog`) |
| `action_plan` | Plano de ação estilo PM Agent em 3 sprints |
| `prompt_lovable` | Prompt pronto para colar no Lovable (MVP + follow-ups) |
| `content` | 8 aulas por sprint |
| `savings` | Economia: ROI e profissionais substituídos/potencializados (usa `price_catalog`) |

## Coerência entre etapas

O prompt de cada etapa recebe `depContext` — os **resumos curtos** das etapas anteriores, vindos do esqueleto gerado no início. Isso mantém a solução coerente sem inflar o input com o conteúdo completo das etapas.

<Note>
  O esqueleto inicial também é gerado por prompt: ele produz título, descrição curta, tags e **uma frase de resumo por etapa** para todas as chaves de `STEP_ORDER`.
</Note>
